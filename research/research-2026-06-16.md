# Hermes Agent Tutorial Expansion Research

## What was investigated

The project already covers the core onboarding, Feishu-friendly workflows, configuration, MCP, memory, and troubleshooting topics. The missing tutorial opportunities are the topics that appear repeatedly in official docs and popular community tutorials but do not yet have clear standalone Learn entries:

- Windows native vs WSL setup choices
- OpenAI-compatible API server and Open WebUI connection
- Cron automation prompt patterns
- Gateway service management and log-first recovery
- Multi-profile gateway operations
- First custom skill creation

The user-provided WaytoAGI Feishu wiki URL redirected to Feishu login in the browsing environment, so it could not be used as a full-text source. Search snippets and WaytoAGI public roundup pages were still useful for topic discovery: they surface Hermes "cold tips", Windows setup, first ten things to try, and automated prompt collections as popular themes.

## Key findings

### Fact

- Official Hermes docs describe one-line installation paths for Linux, macOS, WSL2, native Windows, and Termux. The Windows path now installs dependencies such as uv, Python, Node.js, ripgrep, ffmpeg, and PortableGit under the user-local Hermes directory.
- Official quickstart guidance emphasizes proving one working conversation before adding gateway, cron, skills, routing, or other advanced capabilities.
- Hermes cron can create one-time or recurring tasks, attach one or more skills, run with a workdir, target a profile, deliver to messaging platforms, and run script-only no-agent jobs.
- Gateway service commands differ by platform: Linux uses systemd patterns, macOS uses launchd, and foreground `hermes gateway` remains the simplest debugging path.
- Open WebUI documents Hermes Agent as an OpenAI-compatible API server connection. The documented flow enables `API_SERVER_ENABLED`, sets an API key, starts `hermes gateway`, and connects Open WebUI to `/v1`.
- Hermes skills are documented as task-specific knowledge documents; official examples show creating `~/.hermes/skills/<name>/SKILL.md` with frontmatter and reusable task guidance.

### Interpretation

- The site should avoid copying community tutorials verbatim and instead convert them into lower-risk operating guides: decision trees, verification checklists, prompt templates, and failure boundaries.
- Existing content is strongest on conceptual workflow design; the new additions should make the site more complete for concrete installation, integration, and operations questions.
- The best order for readers is still "prove CLI, then gateway, then automation, then multi-profile or skill authoring."

### Open questions

- The exact WaytoAGI Feishu wiki contents could not be read without Feishu login. If future work gets authenticated access, its Hermes-specific article list can be compared against the new Learn coverage.
- Some community claims around model counts, Windows limitations, and platform support change quickly; official docs should remain the source of truth for commands and compatibility details.

## Content recommendations

1. Add a Windows setup guide that explicitly separates native Windows, WSL2, and Linux/VPS paths.
2. Add an Open WebUI API server guide because it is a common "use Hermes from a UI" tutorial pattern and has clear official setup steps.
3. Add a cron prompt cookbook that teaches narrow scheduled jobs instead of broad "do everything while I sleep" prompts.
4. Add a gateway operations guide that starts with foreground logs, then service install, then platform-specific log commands.
5. Add a multi-profile guide to explain when multiple always-on agents are worth the complexity.
6. Add a first skill guide that keeps the skill small and testable.

## Freshness risk

High for exact commands, supported platforms, provider names, and Windows feature parity. Recheck official Hermes docs and Open WebUI docs before making release or compatibility claims.
